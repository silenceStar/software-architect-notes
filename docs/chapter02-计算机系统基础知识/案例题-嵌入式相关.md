| 对比    | RDB              | AOF              |
| ----- | ---------------- | ---------------- |
| 原理    | **定期保存数据快照**     | **记录写操作命令**      |
| 数据完整性 | 两次快照之间可能丢失数据     | 通常数据丢失较少，取决于同步策略 |
| 文件大小  | **较小、紧凑**        | 通常较大             |
| 恢复速度  | **较快**           | 通常较慢，需要重放命令      |
| 对性能影响 | 备份时可能有一定影响，但总体较低 | 写操作需要记录日志，有一定开销  |
| 适合    | 快速备份、快速恢复        | 对数据持久性要求较高       |

嵌入式实时操作系统：

嵌入式实时操作系统RTOS是当外界事件或数据产生时，能够接受并以足够快的速度予以处理，其处理的结果又能在规定的时间之内来控制生产过程或对处理系统作出快速响应，并控制所有实时任务协调一致运行的嵌入式操作系统。


核心特性：


(1) 确定性（Determinism）：任务执行时间可预测；


(2) 快速中断响应：中断延迟一般低于1μs；


(3) 多任务调度：支持任务优先级和抢占式调度。


提高实时性的关键技术 ：


(1) 抢占式调度：高优先级任务可中断低优先级任务；


(2) 减少上下文切换开销：优化任务切换代码；


(3) 优先级继承协议：避免优先级反转；


硬件加速：使用专用中断控制器降低延迟。


内存分配方式：

|       | 静态堆栈        | 动态堆栈        |
| ----- | ----------- | ----------- |
| 怎么分   | 提前固定分配      | 按实际需求分配     |
| 优点    | 确定、可预测、无碎片  | 灵活、利用率高     |
| 缺点    | 浪费、灵活性差     | 管理复杂、碎片、开销  |
| 核心关键词 | **固定 → 确定** | **动态 → 按需** |

程序里的不同数据，生命周期、大小、管理方式都不一样，所以用不同的内存区域管理，效率更高、也更容易管理。
进程/任务的内存
│
├── 代码区

│

       └── 函数调用、局部变量、返回地址……


腰型通信架构（架构风格）：

BMTS通信机制/通信服务：
计算组件之间进行消息传输；
高可靠、低延迟、低抖动；
通过腰型架构屏蔽底层协议/硬件/网络差异，实现解耦。

事件触发：
发生重要事件才产生消息；
偶发，时间和传输延迟不确定。

速率约束：
消息可偶发产生；
但发送速率不能超过最大规定速率；
保证最大传输时延，抖动受网络负载影响。

时间触发：
按预先规定的时间片/周期发送和接收；
时间确定，抖动可控。

时间触发网络：
TTE、FC、AFDX。


操作系统对进程/作业进行管理和调度的三级调度。
| 调度       | 主要干什么                 | 内存↔外存？    |
| -------- | --------------------- | --------- |
| **高级调度** | 外存作业 → 内存             | ✅ 涉及      |
| **中级调度** | 进程换入/换出               | ✅ 涉及      |
| **低级调度** | 内存中的就绪进程 → CPU        | ❌ **不涉及** |
| 实时调度     | 一种调度需求/策略，不是这里的三级调度层次 | —         |
