# 6.3 数据库设计

## 1. 本节核心思想（100字以内）

数据库设计是将用户需求逐步转化为可运行数据库的过程，依次经历需求分析、概念设计、逻辑设计、物理设计、数据库实施和运行维护。其中，E-R 图设计、关系模式转换、规范化与物理存储设计是核心内容。 :contentReference[oaicite:0]{index=0}

## 2. 考试高频考点

- **考点1：数据库设计的六个阶段**  
  顺序为：需求分析 → 概念结构设计 → 逻辑结构设计 → 物理结构设计 → 数据库实施 → 运行维护。

- **考点2：E-R 图转换为关系模式**  
  实体转换为关系模式；1:1 联系的外键可放任意一方，1:N 联系的外键放在多方，M:N 联系必须建立独立的中间关系。 :contentReference[oaicite:1]{index=1}

- **易混点：概念设计、逻辑设计与物理设计**  
  概念设计主要画 E-R 图，与具体 DBMS 无关；逻辑设计把 E-R 图转换成表；物理设计决定索引、存储结构、数据分布和访问方式。

- **易考选择题：规范化与反规范化**  
  规范化通过分解关系减少数据冗余和更新异常；反规范化有选择地增加冗余，以减少多表连接、提高查询性能，但可能带来数据不一致。 :contentReference[oaicite:2]{index=2}

## 3. 记忆口诀

**需求概逻物，实施再维护；一一随便放，一多放多方，多多建新表。**

解释：

- “需求概逻物，实施再维护”对应数据库设计的六个阶段。
- 1:1 联系的外键可放在任意一方。
- 1:N 联系将“一方”的主键放入“多方”作为外键。
- M:N 联系必须建立独立的中间关系表。
- 概念设计画 E-R 图，逻辑设计形成关系表，物理设计考虑索引和存储。

## 4. 考试一句话总结（精简）

本节最可能考数据库设计六阶段、E-R 图转关系模式，以及规范化与反规范化的区别。
