架构的质量评估重点：
| 质量属性     | 一句话理解              | 典型关键词                  |
| -------- | ------------------ | ---------------------- |
| **性能**   | **快不快、处理能力强不强**    | 响应时间、吞吐量、并发量、容量        |
| **可靠性**  | **系统能否持续、正确地完成任务** | 故障、错误、异常、自我诊断、容错、正确性 ，会不会出错？结果对不对？  |
| **可用性**  | **系统在需要时能否提供服务**    | 正常运行时间、故障切换、快速恢复、降级、容错 ，能不能用？多久恢复？|
| **安全性**  | **能不能防止非法访问和攻击**   | 加密、认证、权限、非法访问、攻击       |
| **可修改性** | **改起来容不容易**        | 修改、维护、调整、扩展            |
| **功能性**  | **能不能完成规定功能**      | 业务功能、功能完整性             |
| **可变性**  | **架构能否演化成不同系统/产品** | 架构变更、产品变体、扩充           |
| **互操作性** | **能不能与其他系统进行交互**   | 接口、协议、标准、数据交换、系统集成     |


# 质量属性效用树、质量属性判断

## 1. 性能（Performance）
- **定义：** 指系统的响应能力，即要经过多长时间才能对某个事件做出响应，或者在某段时间内系统所能处理的事件的个数。
- **指标：** 响应时间、吞吐量。
- **设计策略：** 优先级队列、增加计算资源、减少计算开销、引入并发机制、采用资源调度等。

## 2. 可靠性（Reliability）
- **定义：** 是软件系统在应用或系统错误面前，在意外或错误使用的情况下维持软件系统的功能特性的基本能力。
- **指标：** MTTF、MTBF。
- **设计策略：** 心跳、Ping/Echo、冗余、选举。

## 3. 可用性（Availability）
- **定义：** 是系统能够正常运行的时间比例，经常用两次故障之间的时间长度或在出现故障时系统能够恢复正常的速度来表示。
- **指标：** 故障间隔时间。
- **设计策略：** 心跳、Ping/Echo、冗余、选举。

## 4. 安全性（Security）
- **定义：** 是指系统在向合法用户提供服务的同时，能够阻止非授权用户使用的企图或拒绝服务的能力。
- **指标：** 保密性、完整性、不可抵赖性、可控性。
- **设计策略：** 入侵检测、用户认证、用户授权、追踪审计。

## 5. 可修改性（Modifiability）
- **定义：** 指能够快速地以较高的性能价格比对系统进行变更的能力。通常以某些具体的变更为基准，通过考察这些变更的代价衡量。
- **设计策略：** 接口-实现分类、抽象、信息隐藏。
  
# 质量属性评估必背概念

## 1. 软件架构风格
软件架构风格是指描述特定软件系统组织方式的惯用模式。组织方式描述了系统的组成构件和这些构件的组织方式，惯用模式则反映众多系统共有的结构和语义。

## 2. 架构风险
架构风险是指架构设计中潜在的、存在问题的架构决策所带来的隐患。

## 3. 风险点与非风险点
风险点与非风险点不是以标准专业术语形式出现的，只是一个常规概念。

- **风险点：** 可能引起风险的因素。某个做法如果有隐患，有可能导致一些问题，则为风险点。
- **非风险点：** 如果某件事是可行的、可接受的，则为非风险点。

## 4. 敏感点
敏感点是指为了实现某种特定的质量属性，一个或多个构件所具有的特性。

## 5. 权衡点
权衡点是影响多个质量属性的特性，是多个质量属性的敏感点。

找谁 → 合并成什么功能 → 把功能讲清楚 → 调整模型
识别参与者 → 合并需求获得用例 → 细化用例描述 → 调整用例模型 
| 阶段              | 你可以怎么理解                  |
| --------------- | ------------------------ |
| **1. 识别参与者**    | 找出系统外部有哪些“谁”与系统交互        |
| **2. 合并需求获得用例** | 把参与者提出的需求、系统提供的功能归纳成“用例” |
| **3. 细化用例描述**   | 把每个用例的流程、条件、异常等描述清楚      |
| **4. 调整用例模型**   | 检查、完善和调整参与者、用例及其关系       |


- 1NF：每个属性值必须是不可再分的原子值。
- 2NF：在1NF基础上，消除非主属性对联合码的部分依赖。
- 3NF：在2NF基础上，消除非主属性对码的传递依赖。
- BCNF：每个非平凡函数依赖的决定因素都必须包含候选码。
- 4NF：消除非平凡且决定因素不包含码的多值依赖。

| 范式       | 消除的问题    | 典型特征        | 看到什么就警觉                |
| -------- | -------- | ----------- | ---------------------- |
| **1NF**  | 非原子属性    | 一个字段多个值     | `{A,B,C}`              |
| **2NF**  | **部分依赖** | 非主属性依赖主键一部分 | `(A,B) → C`，同时 `A → C` |
| **3NF**  | **传递依赖** | 非主属性依赖非主属性  | `A → B → C`            |
| **BCNF** | 不合格的决定因素 | 决定因素必须是超键   | `A → B`，但 A 不是超键       |
| **4NF**  | **多值依赖** | 两组独立的一对多    | `A →→ B`(张三 →→ {篮球、游戏}) A →→ C (张三 →→ {英语、日语})，B和C互相独立，需要拆               |
| **5NF**  | **连接依赖** | 关系可以进一步无损分解 | 多表组合关系                 |

| 概念         | 解决什么问题                |
| ---------- | --------------------- |
| **函数依赖**   | 字段之间有什么关系             |
| **无损连接**   | 表拆了以后能不能正确拼回来 ，共同id 进行join        |
| **保持函数依赖** | 表拆了以后，原来的字段关系还能不能继续约束 |
