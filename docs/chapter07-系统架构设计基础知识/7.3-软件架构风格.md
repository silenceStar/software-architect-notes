# 7.3 软件架构风格

## 1. 本节核心思想（100字以内）
软件架构风格是对系统组织方式的抽象模板，通过定义构件、连接件及其约束，形成可复用的系统结构模式，用于指导不同类型软件系统的设计与重用，提升开发效率与系统一致性。

---

## 2. 考试高频考点（尽量精简）

### （1）数据流风格
- 批处理：阶段式顺序处理（ETL）
- 管道-过滤器：流式数据处理（Flink）

### （2）调用/返回风格
- 主程序/子程序：层级调用结构
- 面向对象：对象封装+方法调用
- 层次结构：严格分层（只能相邻层通信）
- C/S结构：两层/三层架构（瘦客户端/胖客户端）

### （3）数据中心风格
- 仓库：所有数据集中管理
- 黑板：黑板 + 知识源 + 控制模块 多知识源协同推理（AI/语音识别）

架构风格：
看到“多个处理步骤，数据依次传递”
        → 管道-过滤器

看到“主程序调用子程序”
        → 主程序/子程序

看到“多个工具/模块共享一个中心数据”
        → 数据仓储

看到“解析、执行一种语言”
        → 解释器

看到“事件发生 → 自动通知其他模块”
        → 事件系统
#### 黑板架构（Blackboard Architecture）

黑板架构用于处理复杂、难以由单一算法一次求解的问题。多个专业模块围绕一个共享工作区逐步补充和修正结果。

| 构成 | 作用 |
| --- | --- |
| **黑板（Blackboard）** | 系统内部的共享数据空间，存放原始问题、中间结果、候选解和处理状态。它**不是用户输入界面或聊天界面**；实现上可为内存中的共享数据结构、数据库或状态存储。 |
| **知识源（Knowledge Source）** | 相互独立的专业模块；各自读取黑板内容，在自己擅长的范围内推理或处理，再把新结果写回黑板。 |
| **控制模块（Controller）** | 监控黑板状态，并决定下一步调用哪个知识源，直至得到可接受的解。 |




```text
用户界面输入问题 → 系统将问题写入黑板
                       ↓
          知识源 A / B / C 读取并补充中间结果
                       ↓
                控制模块持续调度
                       ↓
                    形成最终结果
```

**示例：语音识别。** 黑板可依次保存“原始音频 → 已识别音素 → 候选词 → 候选句子”；声学、词典和语法等知识源分别写入各自的分析结果，控制模块依据当前结果安排下一步处理。

**一句话记忆：**黑板负责共享中间结果，知识源负责分步求解，控制模块负责调度。

### （4）虚拟机风格
- 解释器：自定义语言执行（Python/SQL）
- 规则系统：if-then规则驱动（专家系统）

### （5）独立构件风格
- 进程通信：RPC/消息传递
- 事件系统：发布-订阅（Event-driven）

### （6）C2 风格
- 典型特点就是：组件 + 连接器 + 异步消息传递 + 松耦合

- 理解成：玩家操作 → 事件/消息 → 游戏组件 → 状态更新 → 其他组件
