# 7.5 特定领域软件体系结构（DSSA）Domain-Specific Software Architecture

## 1. 本节核心思想（100字以内）
DSSA是在特定领域中，通过领域分析提取共性需求，设计通用参考架构，并沉淀可复用构件，从而支持该领域多个系统的快速构建与复用的软件体系结构方法。

---

逆向工程：
| 概念                           | 核心动作            | 记忆                |
| ---------------------------- | --------------- | ----------------- |
| **重构 Restructuring**         | 同一抽象层次改变系统描述形式  | **同层改写**          |
| **设计恢复 Design Recovery**     | 从程序中抽取设计信息      | **代码 → 设计**       |
| **逆向工程 Reverse Engineering** | 从低抽象层次恢复高抽象层次表示 | **低 → 高**         |
| **正向工程 Forward Engineering** | 利用设计信息改变/重构现有系统 | **设计 → 系统**       |
| **再工程 Re-engineering**       | 对现有系统重新开发       | **逆向 + 新需求 + 正向** |

## 2. 考试高频考点（尽量精简）
- DSSA定义：领域模型 + 参考需求 + 参考架构 + 可复用构件
- 两种领域划分：
  - 垂直域（完整系统族，行业级）
  - 水平域（跨系统功能）
- 三大阶段：
  - 领域分析（建模需求）
  - 领域设计（形成DSSA）
  - 领域实现（构件复用）
- 四类人员：
| 人员         | 主要作用                           | 一句话记忆       |
| ---------- | ------------------------------ | ----------- |
| **领域专家**   | 提供该领域中已有系统的**需求规约和实现知识**       | **懂业务的人**   |
| **领域分析人员** | 负责**领域分析**，识别领域中的需求、共同点和变化点    | **找需求、找共性** |
| **领域设计人员** | 负责**领域设计**，根据领域分析结果建立 **DSSA** | **设计架构**    |
| **领域实现人员** | 根据 DSSA 进行**具体实现**，开发领域中的应用    | **写代码、落地**  |

- DSSA建立过程五步：
  1. 定义领域范围
  2. 定义领域元素
  3. 定义约束
  4. 建立模型与架构
  5. 构建可复用构件
- 关键思想：复用 + 领域共性抽象 + 架构模板化
