# 15.10 SOA实施的过程

## 实施流程图

```text
选择SOA解决方案
        │
        ▼
   业务流程分析
        │
        ▼
   建立服务模型
 （自顶向下 / 目标分析 / 自底向上）
        │
        ▼
   建立业务对象
（实体/过程/事件）
        │
        ▼
    设计服务接口
（粒度适中、推荐无状态）
        │
        ▼
     建立业务流程
```

---

## 1. 本节核心思想（100字以内）

SOA实施分为两大阶段：首先根据企业实际情况选择合适的SOA方案，然后通过业务流程分析完成服务建模、业务对象设计、服务接口设计和业务流程建模，最终形成可复用、低耦合、易扩展的服务体系。

---

## 2. 考试高频考点

- **考点1：SOA实施流程**（先选择方案，再进行业务流程分析，依次完成服务建模、接口设计和流程建模。）
- **考点2：三种服务建模方法**（自顶向下、自底向上、业务目标分析法，要能区分各自特点。）
- **考点3：业务对象分类**（实体对象表示名词，过程对象表示业务动作，事件对象表示业务事件。）
- **考点4：服务接口设计原则**（接口粒度适中，推荐采用无状态接口，提高复用性和扩展性。）
- **考点5：业务流程分析工具**（Petri 网从流程角度描述和分析复杂系统，既是图形化工具，也具有数学化分析能力。）

- **易混点**（自顶向下是从业务流程拆服务；自底向上是包装遗留系统；业务目标分析是从KPI或业务目标反推服务。）

- **易考选择题**（以下属于遗留资产分析的方法是？答案：**自底向上分析法**。）

---

## 3. 业务流程分析与建模工具

| 工具/概念 | 定位与关注点 | 考试辨析 |
| --- | --- | --- |
| **Petri 网（Petri Net）** | 从流程角度描述、分析复杂系统；可表现活动、状态、并发与同步，既可图形化建模，也可数学化分析。 | 题干出现“流程”“复杂系统”“图形化、数学化”“并发/同步/死锁分析”，优先选 Petri 网。 |
| **BPM** | Business Process Management，业务流程管理的理念和方法体系，覆盖流程设计、执行、监控和优化。 | 是流程管理的总称，不是专门用于数学分析的一种图模型。 |
| **IDEF** | 一组结构化建模方法；常见的 IDEF0 用于功能建模，强调输入、输出、控制和机制。 | 题干强调系统功能及其输入/输出/控制/机制时，考虑 IDEF0。 |
| **DEMO** | 企业建模方法，侧重组织中参与者之间的事务、承诺与沟通。 | 题干强调组织角色、业务事务或交互承诺时，考虑 DEMO。 |

### Petri 网最小示例

```text
订单待支付（状态） → 支付订单（活动） → 已支付（状态）
```

Petri 网通常用“库所（状态）—变迁（活动）—有向弧”表达流程。它尤其适合表示多个活动同时发生、彼此等待或必须同步完成的业务流程。

**一句话记忆：**Petri 网 = **流程 + 并发 + 数学分析**。

## 4. 记忆口诀

**口诀：**

> **先规划，再建模；三法找服务；三类建对象；接口无状态；流程可复用。**

**解释：**

- **先规划**：选择SOA解决方案。
- **再建模**：进行业务流程分析。
- **三法找服务**：自顶向下、业务目标分析、自底向上。
- **三类建对象**：实体、过程、事件。
- **接口无状态**：推荐设计无状态服务接口。
- **流程可复用**：最终形成可编排、可复用的业务流程。
