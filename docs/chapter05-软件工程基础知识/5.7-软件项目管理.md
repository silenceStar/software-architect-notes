# 5.7 软件项目管理

## 1. 本节核心思想

软件项目管理的目标是使软件项目按预定的**成本、进度和质量**完成，核心围绕**进度管理、配置管理、质量管理、风险管理**展开，本质是对人员、产品、过程和项目（4P）进行管理。

---

## 2. 考试高频考点

- **考点1：进度管理与 WBS**
  - WBS（工作分解结构）按“项目 → 任务 → 工作 → 日常活动”逐层分解，**最底层称为工作包**，是最低层次的可交付成果，由唯一主体负责；一般不超过 **6层**。
  - WBS 是制定**进度、资源、成本、风险、采购计划**的重要基础。
  - 任务分解后确定活动的前驱、持续时间、完成日期和里程碑，可形成任务活动图；**甘特图**常用于展示和管理项目进度。

- **考点2：配置、质量与风险管理**
  - **配置管理（SCM）**核心是**版本控制 + 变更控制**：版本控制负责追踪文件修改、分支与合并；变更控制负责让变更有序进行，而不是阻止变更。
  - **质量保证（SQA）**强调**缺陷预防、过程控制、独立审查**，贯穿软件开发全过程；主要任务是**审计与评审、报告、处理不符合问题**。
  - **风险管理**核心是提前识别和处理风险。Boehm模型分为：**风险估计（辨识→分析→排序）+ 风险控制（计划→处理→监督）**。

- **易混点**
  - **版本控制 vs 变更控制**：版本控制管“文件版本怎么变”；变更控制管“变更如何提出、批准和实施”。
  - **SQA vs 软件测试**：SQA侧重**过程和预防缺陷**；软件测试侧重**发现产品中的缺陷**。
  - **ISO 9000 vs CMM**：ISO 9000关注企业的**质量管理体系**；CMM关注软件组织的**软件过程成熟度**。

- **易考选择题**
  - WBS最低层：**工作包**。
  - WBS一般：**不超过6层**。
  - SCM核心：**版本控制、变更控制**。
  - 分支与合并属于：**版本控制**。
  - 变更控制目的：**管理变更，而不是阻止变更**。
  - SQA重点：**预防缺陷、作用于过程、贯穿全过程**。
  - Boehm风险管理：**风险估计 + 风险控制**。
  - 常见进度展示工具：**甘特图**。

## 3. 记忆口诀

> **项目四管：进、配、质、险；  
> WBS拆到底，底层工作包；  
> 配置两控制，版本加变更；  
> 质量重预防，审报加整改；  
> 风险先估计，再控制监督。**

解释：

- **进、配、质、险**：进度、配置、质量、风险管理。
- **工作包**：WBS最低层的可交付成果。
- **版本 + 变更**：SCM两大核心。
- **审报改**：SQA的审计评审、报告、处理不符合问题。
- **先估后控**：风险估计（辨识、分析、排序）→风险控制（计划、处理、监督）。

## 4. 考试一句话总结（精简）

> **重点掌握 WBS工作包、甘特图、SCM的版本/变更控制、SQA过程保证，以及风险管理“估计→控制”的流程。**
