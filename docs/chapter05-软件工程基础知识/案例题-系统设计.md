面向对象设计：
活动图和流程图的3个主要区别
1.活动图是面向对象的，流程图是面向过程的
2.活动图描述的是对象活动的顺序关系和所遵循的规则，着重表现的是系统的行为，而非系统的处理过程。
流程图着重描述过程，主要的控制结构是顺序、分支、循环，各个处理过程之间有着严格的顺序和时间关系。
3.活动图能够表示并发活动的情形，而流程图不能。

面向对象方法的对象类型区分：
                    类
                   /  \
          职责分类      继承角色
          / | \         /    \
       实体 控制 边界   基类(父类)   派生类(子类)


| 维度     | 类型  | 核心问题         | 关键词        |
| ------ | --- | ------------ | ---------- |
| **职责** | 实体类 | 管什么数据？       | 客户、订单、账户   |
|        | 控制类 | 管什么业务？       | 处理、验证、协调   |
|        | 边界类 | 怎么交互？        | 页面、接口、自助机  |
| **继承** | 基类  | 谁是父类？        | 上位概念       |
|        | 派生类 | 谁继承谁？        | 是一种        |
| **关系** | 依赖  | 谁使用谁？        | 使用、调用      |
|        | 关联  | 谁和谁有长期联系？    | 拥有、对应      |
|        | 聚合  | 整体和部分？部分可独立  | 弱拥有        |
|        | 组合  | 整体和部分？部分不可独立 | 强拥有        |
|        | 泛化  | 谁是谁的一种？      | 继承         |
|        | 实现  | 谁实现接口？       | implements |

| 描述                  | 关系     |
| ------------------- | ------ |
| 实物商品是商品的一种          | **泛化** |
| 客户拥有订单              | **关联** |
| 订单由订单明细组成，订单删除明细也删除 | **组合** |
| 商场由员工组成，但员工可以换部门    | **聚合** |
| 订单服务调用支付服务          | **依赖** |
| 微信支付实现支付接口          | **实现** |
