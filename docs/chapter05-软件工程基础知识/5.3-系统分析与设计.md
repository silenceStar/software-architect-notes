## 1. 本节核心思想（100字以内）

系统分析解决“系统做什么”，形成需求规格说明书；系统设计解决“系统怎么做”，包括概要设计和详细设计。常用开发方法分为结构化方法和面向对象方法，设计时应遵循自顶向下、逐步求精、模块化及“高内聚、低耦合”原则。

## 2. 考试高频考点

- **考点1：结构化方法**  
  结构化方法包括结构化分析（SA）、结构化设计（SD）和结构化编程（SP），强调自顶向下、逐步求精和模块化。

- **考点2：核心建模与设计原则**  
  结构化分析主要使用数据流图和数据字典，结构化设计重点考查模块划分、高内聚低耦合及概要设计与详细设计的区别。

- **考点3：结构化设计工具（★★★★★）**
  - 结构化设计是**面向数据流**的设计方法，常用工具包括**盒图（N-S 图）**、**HIPO 图**和**程序流程图**等。
  - **顺序图**是 UML 的交互图，描述对象之间按时间顺序传递的消息，属于面向对象分析与设计工具，**不属于结构化设计工具**。
  - 题干出现“以下不属于结构化设计工具”，在“盒图、HIPO 图、顺序图、程序流程图”中选**顺序图**。

- **易混点：DFD、数据字典、系统结构图和E-R图**  
  DFD描述数据流动和系统功能，数据字典解释DFD中的元素，系统结构图描述模块及调用关系，E-R图描述实体、属性和联系。

DFD 四类对象
E：外部实体 → 人、部门、供应商
P：处理 → 做什么事
D：数据存储 → 文件、数据库
→：数据流 → 传什么数据


第一步：找“题干中有，图中没有”的动作

看到：

发送、提交、生成、传递、访问、更新、检查、返回……

就高度警惕，这是数据流。

第二步：判断箭头两端

问：

谁产生？谁接收？

谁 → 传什么 → 给谁
比如：
送检信息： P3（验证装运部件）——P4（校验部件质量）
P3（验证装运部件）——送检信息--》P4（校验部件质量）
P→E，通知；
P→D，写文件

解析：
送检信息=传递的信息(数据流)
P3为输入
P4为输出

| 关键词               | 关系    |
| ----------------- | ----- |
| **提交、输入、提供**      | E → P |
| **访问、查询、读取**      | D → P |
| **送去、用于、交给下一个处理** | P → P |
| **保存、存储、更新**      | P → D |
| **通知、返回给**        | P → E |

- **易混点：结构化设计工具与 UML 图**
  - 结构化设计：盒图、HIPO 图、程序流程图等。
  - 面向对象/UML：顺序图、类图、用例图、状态图等。

- **易考选择题：耦合、内聚与面向对象类的分类**  
  耦合应越低越好，内聚应越高越好；功能内聚最高、偶然内聚最低，内容耦合最强；面向对象设计中的类分为实体类、控制类和边界类。

## 3. 记忆口诀

**分析做什么，设计怎么做；  
DFD画数据，字典作解释；  
结构图看模块，E-R看数据；  
高内聚、低耦合，封装继承加多态。**

解释：

- 系统分析明确需求，系统设计给出实现方案；
- DFD描述数据流，数据字典补充各元素的定义；
- 系统结构图反映模块关系，E-R图反映实体关系；
- 软件设计追求高内聚、低耦合；
- 面向对象的核心特征是封装、继承和多态。

## 4. 考试一句话总结（精简）

本节最可能考结构化与面向对象方法的区别、DFD与各类设计图的用途，以及高内聚低耦合、耦合内聚排序和实体类/控制类/边界类。
