# 5.3 系统分析与设计

## 1. 本节核心思想（100字以内）

系统分析解决“系统做什么”，形成需求规格说明书；系统设计解决“系统怎么做”，包括概要设计和详细设计。常用开发方法分为结构化方法和面向对象方法，设计时应遵循自顶向下、逐步求精、模块化及“高内聚、低耦合”原则。

## 2. 考试高频考点

- **考点1：结构化方法**  
  结构化方法包括结构化分析（SA）、结构化设计（SD）和结构化编程（SP），强调自顶向下、逐步求精和模块化。

- **考点2：核心建模与设计原则**  
  结构化分析主要使用数据流图和数据字典，结构化设计重点考查模块划分、高内聚低耦合及概要设计与详细设计的区别。

- **易混点：DFD、数据字典、系统结构图和E-R图**  
  DFD描述数据流动和系统功能，数据字典解释DFD中的元素，系统结构图描述模块及调用关系，E-R图描述实体、属性和联系。

- **易考选择题：耦合、内聚与面向对象类的分类**  
  耦合应越低越好，内聚应越高越好；功能内聚最高、偶然内聚最低，内容耦合最强；面向对象设计中的类分为实体类、控制类和边界类。

## 3. 记忆口诀

**分析做什么，设计怎么做；  
DFD画数据，字典作解释；  
结构图看模块，E-R看数据；  
高内聚、低耦合，封装继承加多态。**

解释：

- 系统分析明确需求，系统设计给出实现方案；
- DFD描述数据流，数据字典补充各元素的定义；
- 系统结构图反映模块关系，E-R图反映实体关系；
- 软件设计追求高内聚、低耦合；
- 面向对象的核心特征是封装、继承和多态。

## 4. 考试一句话总结（精简）

本节最可能考结构化与面向对象方法的区别、DFD与各类设计图的用途，以及高内聚低耦合、耦合内聚排序和实体类/控制类/边界类。
