架构评估重点：
| 看到题目                   | 想到      |
| ---------------------- | ------- |
| **3秒、5000请求/秒、1000并发** | 🚀 性能   |
| **很少故障、连续运行、故障率**      | 🛠️ 可靠性 |
| **主备、故障切换、99.99%**     | 🟢 可用性  |
| **密码、权限、加密、认证**        | 🔐 安全性  |
| **需求变化、修改模块、2周完成**     | 🔧 可修改性 |
| **能不能正确完成业务功能**        | ⚙️ 功能性  |
| **不同客户、配置、定制、不同版本**    | 🔄 可变性  |
| **接口、第三方系统、数据交换**      | 🔌 互操作性 |

| 架构策略 / 技术     | 主要提高     | 记忆理由               |
| ------------- | -------- | ------------------ |
| **Ping/Echo** | **可用性**  | 检测故障、及时发现不可用       |
| **限制访问**      | **安全性**  | 防止未授权访问            |
| **运行时注册**     | **可修改性** | 运行时可动态增加/替换组件      |
| **接口-实现分离**   | **可修改性** | 修改实现时减少对其他模块影响     |
| **主动冗余**      | **可用性**  | 多份同时运行，故障可继续提供服务   |
| **队列调度**      | **性能**   | 合理安排任务，提高吞吐量、资源利用率 |
| **信息隐藏**      | **可修改性** | 隐藏内部实现，降低模块间耦合     |
| **记录-回放**     | **可测试性** | 记录输入，之后重复回放进行测试    |
