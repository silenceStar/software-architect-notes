持久层框架:
                    持久层框架
                       │
             ┌─────────┴─────────┐
             ↓                   ↓
         Hibernate             MyBatis
             │                   │
            ORM                SQL映射
             │                   │
       对象驱动                 SQL驱动
             │                   │
       自动生成SQL             自己写SQL
             │                   │
      开发效率高               灵活性高
      CRUD方便                 复杂查询强
      抽象程度高               SQL控制强
             │                   │
             ↓                   ↓
      “少写SQL，省事”       “自己掌控SQL”


若需在Hibernate与MyBatis中选择一个作为持久层框架，请从性能、灵活性、复杂查询支持三个维度阐述选择依据
| 维度       | Hibernate                                                                     | MyBatis                   |
| -------- | -------------------------------                                                | ------------------------- |
| **性能**   | ORM(Object-Relational Mapping)全自动映射，开发效率高；复杂场景可能产生额外开销      | 半自动，SQL可控，容易针对SQL优化，性能更容易精细控制 |
| **灵活性**  | 封装程度高，开发方便，但SQL控制相对弱                                               | 灵活，SQL完全由开发者控制            |
| **复杂查询** | 简单CRUD很方便；复杂查询可能需要HQL/Criteria等                                     | **复杂SQL优势明显**，可直接编写SQL    |


性能：Hibernate是全自动化映射，会对性能造成额外开销
MyBatis属于半自动化，可以自己写sql，以进行更精细化控制，优化，对性能提升有帮助

灵活性：Hibernate封装程度高，而MyBatis可以自己写sql， 对于复杂sql处理，Hibernate虽然有HQL支持，但还是mybatis的动态sql更加灵活

复杂查询：MyBatis可以自己写复杂sql，实现方便。Hibernate的HQL对于复杂sql的支持有限，sql不方便优化等问题。
