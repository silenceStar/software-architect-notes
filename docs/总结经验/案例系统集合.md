智能安防系统
采用四层架构：
感知层       → 采数据
   ↓
边缘层       → 就近处理、实时响应
   ↓
AI决策层     → AI分析、训练、决策
   ↓
应用层       → 安防业务、展示、控制

感知层：通过摄像头、传感器、RFID等设备，对人员、车辆、环境等进行识别和数据采集，为系统提供原始数据。
边缘层：靠近数据源对数据进行过滤、清洗、融合和实时分析，并执行AI推理和快速响应，在网络异常时可提供一定的离线自治能力。
AI决策层：对边缘上传的数据进行集中分析，利用人工智能模型进行目标识别、风险分析、预测和决策，并负责模型训练、更新及策略下发。
应用层：面向安防业务提供监控、告警、可视化、查询和联动控制等功能，实现人与系统的交互以及业务应用。

优点：
低延迟、实时性强：边缘层靠近数据源处理，减少数据上传云端的传输和等待时间。
离线自治能力强：网络中断或云端不可用时，仍可本地处理数据和AI推理，维持基本业务运行。
降低网络带宽压力：边缘侧过滤、清洗、聚合数据，仅上传有价值的数据，减少原始数据传输。
降低中心计算压力：将部分计算任务下沉至边缘节点，减少中心AI平台的计算负担。
提高数据隐私与安全性：敏感数据可在本地处理，减少原始数据在网络中的传输。
分层解耦，便于扩展维护：感知、边缘、AI决策和应用相互解耦，可独立升级和扩展。

缺点：
①系统复杂度高：设备、边缘节点和AI平台数量多，架构复杂，部署和运维成本较高。
②资源受限：边缘设备计算、存储和功耗有限，难以部署复杂的大规模AI模型。
③协同复杂：边缘节点与AI决策层之间需要进行数据、模型和策略同步，容易产生数据及模型一致性问题。
④安全风险增加：边缘节点分布广、数量多，设备和网络暴露面扩大，安全防护和统一管理难度较高。
⑤异构性强：不同传感器、设备、通信协议和计算环境存在差异，兼容、升级和统一管理困难。

【问题1】简要讨论C/S和B/S两种架构风格各自的优点和缺点。
C/S架构

优点：

交互性强、响应快：客户端处理部分业务，网络压力较小，适合大量数据处理。
安全性较好：具有较安全的存取模式。
技术成熟：开发模式成熟，分工明确。
功能丰富：客户端可充分利用本地资源，适合复杂业务。

缺点：

部署维护困难：每台客户端都需要安装软件，升级和维护工作量大。
开发成本较高：客户端程序复杂，开发和维护成本高。
跨平台能力差：不同操作系统可能需要不同客户端。
数据集成困难：客户端直接访问数据库时，会增加数据库安全风险。
B/S架构

优点：

部署维护简单：客户端只需浏览器，无需安装专用软件。
升级方便：主要在服务器端升级，用户无需逐台更新。
跨平台、开放性好：通过浏览器访问，可应用于广域网。
扩展性较好：便于系统统一管理和扩展。

缺点：

响应速度相对较慢：较依赖网络和服务器处理能力。
交互性相对较弱：复杂交互和大量数据处理能力不如C/S。
安全性较难控制：系统通过网络和浏览器访问，安全防护要求较高。
服务器压力较大：大量业务处理集中在服务器端。

请说明微服务架构的优点和缺点。

微服务架构：
**概念：**  
微服务架构将大型应用按照业务功能拆分为多个相对独立的服务，各服务可独立开发、部署、运行和扩展，并通过网络接口通信，实现服务间松耦合。

**优点：**
- **独立部署**：服务可独立发布、升级。
- **松耦合**：服务通过接口通信，降低依赖。
- **独立扩展**：可针对高负载服务单独扩容。
- **独立演进**：不同服务可独立开发和迭代。
- **技术异构**：不同服务可采用不同技术栈。

**缺点：**
- **通信复杂**：网络调用带来延迟、超时和故障。
- **事务复杂**：跨服务产生分布式事务和数据一致性问题。
- **运维复杂**：需要服务发现、负载均衡、熔断、限流、监控等。
- **部署测试复杂**：服务数量增加，自动化要求更高。
- **性能开销**：网络通信增加系统开销。

【问题1】（9分）

在订单处理系统中，可能需要对订单状态进行更新，如从“待支付”变为“已支付”。如果多个服务实例同时处理同一个订单，可能会导致订单状态不一致。使用分布式锁可以确保在同一时间内只有一个服务实例能够修改订单状态。
为此架构师李工提出了采用redis作为分布式锁，而架构师王工提出采用数据库作为分布式锁的方案。请写出使用基于数据库的分布式锁和基于redis的分布式锁的优点和缺陷。

数据库：
优点：
实现简单：数据库本身就支持事务、锁功能，不需要引入额外组件
可靠性高：锁和业务数据通常在同一个数据库中，便于保证数据的一致性
数据持久化：数据库本身就具有数据持久化能力和故障恢复能力


缺点：
性能有限：高并发情况下， 大量锁请求会增加数据库负担，容易成为数据库性能瓶颈。
扩展性差：数据库本身成为分布式锁的集中竞争点，难以随服务节点增加而线性扩展
影响业务：大量事务等待数据库锁，会影响业务的正常使用，会导致响应时间增加和形成死锁


redis：
优点：
性能高：redis是基于内存的，锁的获取和释放速度很快，适合高并发场景
并发能力强：可以将锁操作从数据库中剥离，降低数据库压力。
适合分布式环境：多个服务实例可以通过共享redis实例协调访问
支持过期机制：设置过期时间，避免服务异常后锁的长期占用

缺点：
可靠性和一致性需要额外保证：redis节点故障、网络异常等情况可能导致锁的获取和释放异常
实现复杂度高：需要正确的处理锁超时、误删锁、续期、故障转移等问题
增加系统组件和运维成本：需要额外部署和运维redis

正确答案：

（2）生命线（Lifeline），生命线表示对象在交互过程中存在的时间线。

（5）交互片段（Interaction Fragment），交互片段用于表示顺序图中的一组特殊交互，如循环、条件分支等。
