面向对象的开发方法：
     最高层：业务流程
     ↓
     一组长期运行的动作/活动
     ↓
     第二层：服务
     ↓
     操作的逻辑分组
     ↓
     最低层：服务操作
     ↓
     单个逻辑单元 + 结构化接口 + 结构化响应

| 层次 | 概念                          | 怎么理解              |
| -- | --------------------------- | ----------------- |
| 低  | **服务操作（Service Operation）** | 单个逻辑单元，有接口，返回响应   |
| 中  | **服务（Service）**             | 一组相关操作的逻辑分组       |
| 高  | **业务流程（Business Process）**  | 为实现业务目标而执行的一组长期活动 |





用例关系：
└── 三、用例之间的关系
       │
       ├── <<include>> → 必须包含
       ├── <<extend>>  → 条件扩展
       └── 泛化 → 一般用例/特殊用例

| 关系               | 关键词       | 核心意思                       |
| ---------------- | --------- | -------------------------- |
| `<<include>>` 包含 | **必须执行**  | 一个用例执行时，必然包含另一个用例，必然触发   虚线A-->B       |
| `<<extend>>` 扩展  | **条件执行**  | 在特定条件下，对基础用例增加额外行为，满足条件才会触发 虚线A<--B        |
| 泛化               | **一般/特殊** | 一个用例是另一个用例的特殊形式，子继承父行为，实线A<——B。付款<——支付宝付款、微信付款 |


UML/面向对象建模的通用关系体系：
                    类
                   /  \
          职责分类      继承角色
          / | \         /    \
       实体 控制 边界   基类(父类)   派生类(子类)


| 维度     | 类型  | 核心问题         | 关键词        |
| ------ | --- | ------------ | ---------- |
| **职责** | 实体类 | 管什么数据？       | 客户、订单、账户   |
|        | 控制类 | 管什么业务？       | 处理、验证、协调   |
|        | 边界类 | 怎么交互？        | 页面、接口、自助机  |
| **继承** | 基类  | 谁是父类？        | 上位概念       |
|        | 派生类 | 谁继承谁？        | 是一种        |
| **关系** | 依赖  | 谁使用谁？        | 使用、调用      |
|        | 关联  | 谁和谁有长期联系？    | 拥有、对应      |
|        | 聚合  | 整体和部分？部分可独立  | 弱拥有        |
|        | 组合  | 整体和部分？部分不可独立 | 强拥有        |
|        | 泛化  | 谁是谁的一种？      | 继承         |
|        | 实现  | 谁实现接口？       | implements |


| 关系     | 你可以这样记                  |
| ------ | ----------------------- |
| **泛化** | **是……的一种**，子类继承父类的特征和行为 |
| **依赖** | **使用**，一个类的实现需要另一个类的协助  |
| **关联** | **有稳定的业务联系/对应关系**       |
| **聚合** | **整体和部分**，部分可以离开整体独立存在  |
| **组合** | **整体和部分**，部分不能脱离整体独立存在  |
| **实现** | **类实现接口**，实现接口规定的行为     |



| 描述                  | 关系     |
| ------------------- | ------ |
| 实物商品是商品的一种          | **泛化** |
| 客户拥有订单              | **关联** |
| 订单由订单明细组成，订单删除明细也删除 | **组合** |
| 商场由员工组成，但员工可以换部门    | **聚合** |
| 订单服务调用支付服务          | **依赖** |
| 微信支付实现支付接口          | **实现** |
