系统可靠性的定义：
软件可靠性是指软件在规定条件、规定时间内完成规定功能的能力，本质是软件不发生失效的概率。

系统在规定条件、规定时间内 完成规定功能的能力，本质是系统不发生实效的概率，

4个子特性：
### 软件可靠性的4个子特性
| 子特性         | 你怎么理解               |
| ----------- | ------------------- |
| **成熟性**     | 系统在正常运行过程中，发生故障的概率低 |
| **容错性**     | 出现故障时，系统仍能继续运行      |
| **易恢复性**    | 出现故障后，能够快速恢复正常      |
| **可靠性的依从性** | 遵循相关标准、规范、约定的可靠性要求  |

成熟性、容错性、易恢复性、可靠性的依从性


提高系统可靠性一般采用以下4类技术：
提高系统可靠性
│
├── 冗余技术
│     └── 多副本、备用模块
│
├── 软件容错技术
│     ├── N版本程序设计（多个实现方法-》表决正确结果-〉向前）
│     ├── 恢复块（主块-》验证测试-〉输出正确结果-》回退）
│     └── 检错 + 恢复 （发现错误，再进行恢复）
│
├── 双机容错技术
│     └── 主机 + 备用机
│          └── 心跳检测、故障切换
│
└── 集群技术
      └── 多节点共同提供服务


N版本程序设计、恢复块比较
恢复块：单机验收，错了回退，实时性差。
N版本：多机表决，不退向前，实时性好。

| 比较项    | 恢复块方法      | N版本程序设计  |
| ------ | ---------- | -------- |
| 硬件运行环境 | **单机**     | **多机**   |
| 错误检测方法 | **验证测试程序** | **表决**   |
| 恢复策略   | **反向恢复**   | **向前恢复** |
| 实时性    | **差**      | **好**    |




硬件可靠性特征与其对应的软件可靠性特征之间的差异之处：
| 硬件可靠性特征                 | 软件可靠性特征               | 差异/相似                                                   |
| ----------------------- | --------------------- | ------------------------------------------------------- |
| 硬件故障具有**物理性**           | 软件故障主要来自**设计缺陷**      | **差异**：硬件可能因为磨损、老化、环境影响发生故障；软件通常因为需求、设计、编码中的错误而失效       |
| 硬件会随时间发生**退化**          | 软件一般**不会随时间退化**       | **差异**：硬件使用时间越长，老化、磨损导致故障率可能增加；软件只要不修改，本身不会因为“使用次数多”而磨损 |
| 硬件可以通过**维修、更换**恢复       | 软件通常通过**修改、更新程序**消除缺陷 | **差异**：硬件坏了可以换零件；软件发现 Bug 后需要修改代码                       |
| 硬件具有一定的**可复制性**，但制造存在差异 | 软件具有**高度可复制性**        | **相似但有差异**：软件复制成本低，复制出的程序通常完全一致；硬件即使型号相同，也存在制造偏差        |
| 硬件可靠性会受到**环境因素**影响      | 软件可靠性对物理环境**不敏感**     | **差异**：温度、湿度、振动等会直接影响硬件；软件本身没有物理磨损                      |


物理性，会因磨损、老化等发生故障
软件不会有物理性，不会随时间发生变化，失效多由设计缺陷引起
硬件维修、更换恢复至初始状态，软件因维护会因为需求、bug进行更改，回不到初始状态
硬件复制的时候，制造存在一定差异，软件一份代码可以进行完整复制，不存在差异
硬件迭代周期漫长，软件迭代周期一般比较快


设计银行自助服务系统时，如何确保系统的可靠性：
答题要全面，当作自己就在设计该系统的可靠性：

              系统可靠性
                   │
       ┌───────────┼───────────┐
       ↓           ↓           ↓
    发现故障      抗住故障      减少故障
       │           │           │
     监控        冗余/容错     好的设计
       │           │           │
   检测+恢复    热备+集群      高内聚低耦合
                              │
                         成熟构件

设计阶段考虑系统的可靠性
监控机制：能够及时发现故障，并启动恢复方案
双机热备：主服务器故障，备用机器立刻切换
软件层面：异常处理、事务回滚等
架构层面：高内聚、低耦合，降低代码复杂度
