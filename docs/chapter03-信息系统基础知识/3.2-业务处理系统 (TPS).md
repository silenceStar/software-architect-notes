# 3.2 业务处理系统（TPS）

## 1. 本节核心思想（100字以内）

业务处理系统（TPS）是服务于企业基层作业层的信息系统，主要对日常、大量、重复且高度结构化的业务数据进行输入、处理、存储、输出和查询。它是其他管理信息系统的数据基础，强调处理的准确性、及时性、可靠性和高效率。

### TPS 数据处理周期

```mermaid

    A[数据输入] --> B[数据处理]
    B --> C[数据库维护]
    C --> D[文件与报表生成]
    D --> E[查询处理]
```

## 2. 考试高频考点

* **考点1：TPS的定位与作用**
  TPS主要服务于组织的基层作业层，处理财务、销售、库存、工资、订单等日常事务，减轻人工处理原始数据的负担。

* **考点2：TPS的五项基本功能**
  TPS的数据处理周期包括数据输入、数据处理、数据库维护、文件报表生成和查询处理，其中数据处理又分为批处理和联机事务处理。

* **考点3：批处理与联机事务处理的区别**
  批处理是将事务积累到一定时间后集中处理，成本较低但实时性差；OLTP是在事务发生后立即处理并更新数据库，实时性强但成本和可靠性要求更高。

* **考点4：TPS输出文件的类型**
  行动文件用于直接执行某项业务，信息文件用于说明某项业务已经发生，周转文件交给接收者处理后还需要返回发送者。

* **易混点：TPS、MIS与DSS的区别**
  TPS负责记录和处理原始业务数据；MIS对TPS数据进行统计汇总，为中层管理提供报表；DSS通过模型和分析方法辅助管理者进行半结构化或非结构化决策。

* **易混点：批处理不等于离线系统**
  批处理强调数据先积累、后集中处理；OLTP强调事务发生后立即处理，二者的核心区别是处理时机和实时性。

* **易考选择题：以下哪项属于TPS**
  银行存取款系统、超市收银系统、工资管理系统、库存管理系统和航空订票系统都属于TPS；企业战略规划和市场趋势预测通常不属于TPS。

* **易考选择题：TPS适合采用哪种开发方法**
  TPS处理的业务流程固定、结构化程度高，因此适合采用结构化生命周期法开发，并且许多TPS可以直接购买商品化软件后进行二次开发。

## 3. 记忆口诀

### 口诀一：输、处、库、报、查

* **输**：数据输入，将原始业务数据录入系统。
* **处**：数据处理，包括批处理和联机事务处理。
* **库**：数据库维护，包括检索、增加、修改和删除。
* **报**：生成文件、凭证和业务报表。
* **查**：根据用户权限提供批次查询或实时查询。

### 口诀二：批量等一等，联机马上办

* **批处理**：数据先积累，再按照每日、每周或每月集中处理，经济但不够及时。
* **联机事务处理**：事务发生后立即处理、立即更新、立即返回结果，及时但成本较高。

### 口诀三：行动办事，信息告知，周转返回

* **行动文件**：接收者凭文件执行采购、付款、发货等业务。
* **信息文件**：通知接收者某项业务已经发生。
* **周转文件**：发送给接收者后，处理完还需要返回发送者。

## 4. 考试一句话总结（精简）

TPS服务于基层作业层，重点考查五项基本功能、批处理与OLTP的区别，以及行动、信息、周转三类输出文件。
