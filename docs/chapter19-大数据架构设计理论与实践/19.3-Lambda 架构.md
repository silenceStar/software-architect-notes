# 19.3 Lambda 架构

## 1. 本节核心思想

Lambda 架构通过**批处理层、加速层和服务层**同时处理历史全量数据与实时增量数据，以批处理保证最终准确，以流处理保证低延迟，兼顾容错性、可扩展性和查询效率。

```text
数据源
 ├──→ 批处理层：全量计算 → Batch View ──┐
 └──→ 加速层：增量计算 → Real-time View ─┤
                                           ↓
                                    服务层合并查询
```

## 2. 考试高频考点

* **考点1：Lambda 架构的三层结构**
  批处理层保存不可变的全量原始数据并生成 Batch View；加速层处理最新增量数据并生成 Real-time View；服务层合并两类视图并响应查询。

* **考点2：最终精度与容错机制**
  加速层先提供低延迟的近似结果，批处理层随后根据完整原始数据重新计算并替换实时结果，从而修正错误并达到最终准确。

* **考点3：Monoid 特性**
  满足结合律的运算可拆分到多台机器并行计算，再合并局部结果，如求和、计数、最大值；平均值可拆成“总和÷总数量”后合并。

* **考点4：Lambda 架构的优缺点**
  优点是容错性好、查询灵活、易于横向扩展和增加视图；缺点是批处理与流处理通常需要维护两套业务逻辑，编码、部署和迁移成本较高。

* **易混点：批处理层、加速层与服务层的职责**
  批处理层负责“全量、准确”，加速层负责“增量、实时”，服务层负责“合并、查询”；服务层本身不负责重新计算全部数据。

* **易混点：最终精度与最终一致性**
  最终精度强调实时近似结果最终被准确结果替代；最终一致性强调不同处理层或数据副本经过一段时间后状态趋于一致。

* **易混点：Lambda 与事件溯源、CQRS**
  Lambda 借鉴事件溯源的不可变事件存储思想，也体现 CQRS 的读写分离，但 Lambda 的重点是批流结合的大数据处理架构。

* **易考选择题：加速层处理的数据范围**
  Speed Layer 只处理尚未被最新 Batch View 覆盖的近期增量数据，而不是处理全部历史数据。

* **易考选择题：典型技术选型**
  HDFS/Hadoop 可用于主数据集和批处理，Kafka 用于数据传输，Spark、Storm 或 Flink 用于计算，HBase 或 Cassandra 可作为服务层存储；具体组件并非固定。

## 3. 记忆口诀

**批全量，速增量；批求准，速求快；服务合视图，最终纠偏差。**

解释：

* **批全量**：批处理层处理全部历史数据；
* **速增量**：加速层处理最近产生的实时数据；
* **批求准**：批处理结果完整、准确，但时延较高；
* **速求快**：实时结果延迟低，但可能暂时近似；
* **服务合视图**：服务层合并 Batch View 与 Real-time View；
* **最终纠偏差**：批处理重新计算后，可修正实时处理中的错误。

## 4. 考试一句话总结

Lambda 架构最可能考三层职责、批流视图合并、最终精度，以及维护批流两套逻辑带来的高复杂度。
