## 2026-08-20｜第 5 章｜净室软件工程（CSE）

- 题型：单选
- 来源：软考达人-回忆版
- 错误类型：`概念绝对化`
- 题目要点：以下关于净室软件工程的描述中，哪项不正确？
  - A. 净室软件工程是一种以合理成本开发高质量软件的方法
  - B. 净室软件工程无需进行传统的模块测试
  - C. 净室软件工程的理论基础主要是函数理论和抽样理论
  - D. 采用正确性验证，使得净室项目的软件质量有了极大的提高
- 我的答案：C
- 正确答案：B
- 正确解析：净室软件工程以正确性验证、统计测试等手段提高质量，但“无需进行传统的模块测试”表述过于绝对。实际开发中，工程师对语言和环境不熟悉，以及编译器、操作系统等缺陷，都可能带来未预期错误，因此仍可能需要传统模块测试。C 中“函数理论和抽样理论”是本题采用的理论基础表述。
- 我为什么会错：把“强调正确性验证、弱化依赖测试”误解成了“完全不做模块测试”，同时误判了 C 的术语表述。
- 以后如何避免：看到“无需、完全、不需要”等绝对表述时，先判断是否忽略了工程环境与工具链缺陷；牢记本题口径为“函数理论 + 抽样理论”。
- 关联笔记：[5.5 净室软件工程（CSE）](../chapter05-软件工程基础知识/5.5-净室软件工程（CSE）.md)

## 2026-08-20｜第 5 章｜基于构件的软件工程（CBSE）

- 题型：单选
- 来源：章节练习
- 错误类型：`构件特性混淆`
- 题目要点：对于可组装的构件，所有外部交互必须通过公开定义的接口进行，同时还必须限制自身信息的外部访问。此描述对应哪项构件特性？
  - A. 可组装性
  - B. 可部署性
  - C. 文档化
  - D. 独立性
- 正确答案：A（可组装性）
- 正确解析：可组装性要求构件通过公开、明确的接口与外界交互，并隐藏内部实现与信息，以便与其他构件安全组合。可部署性强调可在构件平台独立运行；“二进制形式、部署前无须编译”也是其相关描述。
- 我为什么会错：混淆了“接口封装、便于组装”与“可独立运行、部署”的不同侧重点。
- 以后如何避免：看到“公开接口、限制外部访问”立即对应可组装性；看到“独立实体、构件平台运行、二进制部署”对应可部署性。
- 关联笔记：[5.6 基于构件的软件工程（CBSE）](../chapter05-软件工程基础知识/5.6-基于构件的软件工程（CBSE）.md)

## 2026-08-20｜第 8 章｜ATAM 效用树

- 题型：单选
- 来源：章节练习
- 错误类型：`层级结构混淆`
- 题目要点：在软件架构评估中，ATAM 方法采用效用树对质量属性进行分类和优先级排序。效用树的结构包括什么？
  - A. 树根 → 质量属性 → 属性分类 → 质量属性场景（叶子节点）
  - B. 树根 → 属性分类 → 属性描述 → 质量属性场景（叶子节点）
  - C. 树根 → 质量属性 → 属性描述 → 质量属性场景（叶子节点）
  - D. 树根 → 功能需求 → 需求描述 → 质量属性场景（叶子节点）
- 我的答案：C
- 正确答案：A
- 正确解析：ATAM 的效用树以树根表示质量属性高层目标，逐层展开为质量属性、属性分类，最后以可度量、可评估的质量属性场景作为叶子节点。中间层应为“属性分类”，不是“属性描述”。
- 我为什么会错：将属性分类误认为属性描述，漏掉了效用树对质量属性进行分层分类的结构。
- 以后如何避免：记忆结构为“根—质—类—景”：树根 → 质量属性 → 属性分类 → 场景。
- 关联笔记：[8.2 系统架构评估](../chapter08-系统质量属性与架构评估/8.2-系统架构评估.md)

## 2026-08-21｜第 5 章｜构件组装的接口不兼容

- 题型：单选
- 来源：构件组装练习
- 错误类型：`概念混淆`
- 题目要点：构件组装时，如果一个构件的提供接口是另一个构件请求接口的一个子集，属于哪种接口不兼容情况？
  - A. 参数不兼容
  - B. 操作不兼容
  - C. 返回值不匹配
  - D. 操作不完备
- 我的答案：未记录（对“子集”关系理解不牢）
- 正确答案：D（操作不完备）
- 正确解析：请求接口表示使用方所需的操作，提供接口表示提供方实际支持的操作。若提供接口是请求接口的子集，说明提供方缺少部分被请求的操作，不能完整满足使用方需求，属于操作不完备。
- 我为什么会错：没有将集合的“子集”关系映射为功能范围的大小关系，容易把缺少操作误认为参数或返回值的问题。
- 以后如何避免：看到“提供接口 ⊂ 请求接口”立即判断为“提供方功能不够”→ 操作不完备。例：请求方需要“查询、取消、修改订单”，提供方只支持“查询、取消订单”，则缺少“修改订单”。
- 关联笔记：[5.6 基于构件的软件工程（CBSE）](../chapter05-软件工程基础知识/5.6-基于构件的软件工程（CBSE）.md)

## 2026-08-21｜第 8 章｜质量属性场景六要素

- 题型：单选
- 来源：质量属性场景描述练习
- 错误类型：`概念混淆`
- 题目要点：为精确描述软件系统的质量属性，通常采用质量属性场景。其中，哪个要素描述“刺激到达后所采取的行动”？
  - A. 响应度量
  - B. 制品
  - C. 响应
  - D. 刺激
- 我的答案：未记录（对六要素含义理解不牢）
- 正确答案：C（响应）
- 正确解析：质量属性场景由刺激源、刺激、环境、制品、响应和响应度量构成。“响应”是系统在刺激到达后采取的行动；“响应度量”则是对该行动结果的可测试、可量化标准。
- 我为什么会错：对“响应”和“响应度量”等相邻概念缺少具体场景映射，记住了名词但没有理解其先后关系。
- 以后如何避免：按“谁—发生什么—在什么环境—影响什么—系统怎么做—做到什么标准”理解六要素。例：1000 名用户同时查询订单时，订单服务返回结果（响应），且 95% 请求在 2 秒内完成（响应度量）。
- 关联笔记：[8.1 软件系统质量属性](../chapter08-系统质量属性与架构评估/8.1-软件系统质量属性.md)
